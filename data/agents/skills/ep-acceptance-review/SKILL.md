# 竣工环境保护验收报告审核技能

本技能用于对《建设项目竣工环境保护验收报告》Word 文档执行**独立审核**（编制与审核职责分离，
符合 CMA 三级审核管理理念）。审核对象可以是 ep-acceptance-report 技能生成的报告，
也可以是用户手工编制或第三方提供的任何验收报告 docx。

## 何时使用

- 用户要求审核/检查/复核/质检一份验收报告（"审一遍""核对图片和格式""检查细节"）。
- 用户要求核对报告中的图片是否插入正确（位置、图注、清晰度、编号）。
- 用户要求检查报告格式（章节、字体、表格、编号）与内容细节（占位符、数据一致性、结论）。
- 报告交付前需要一道独立质控关卡（生成技能第 5 步只有自检，不替代本技能）。

## 审核原则

- **编制与审核分离**：本技能独立于 ep-acceptance-report 运行，不修改报告本身，
  只输出《报告审核意见单》。修改由用户（或编制技能）按意见单执行。
- **三级分级**：P0 致命（不得出具）/ P1 严重（必须修改后复审）/ P2 一般（建议修改）。
- **不虚构判断**：监测数据、标准限值、达标结论的核对以报告与源资料为准；
  无法确认的项标注"待人工确认"，不得臆断。
- **双重依据**：程序化检查（脚本）给出确定性问题；AI 视觉与语义检查给出需要
  判断力的问题；两者汇总为一份意见单，注明每条的来源（脚本/AI/人工）。

## 工作流程

### 第 1 步：确认审核对象与输入

向用户确认或自动识别：

- **报告文件**：待审 .docx 路径（必填）。
- **源数据**（可选）：编制技能产出的 `acceptance_data.json`，用于正文与源数据一致性比对；
  缺失时跳过 JSON 比对项，改为报告内部一致性检查。
- **审核重点**（可选）：用户可指定侧重（如图片核对 / 格式核对 / 内容核对）；
  默认执行全部三层检查。

### 第 2 步：程序化检查（脚本层）

运行检查脚本，获得确定性问题的结构化结果：

```bash
.../envs/default/Scripts/python.exe \
  (skill_dir)/scripts/check_acceptance_docx.py \
  --docx 验收报告.docx \
  [--data acceptance_data.json] \
  [--out issues.json]
```

脚本自动检查（详见 `references/review_checklist.md` 的"可程序化检查项"）：
章节完整性、占位符残留、附图/附件编号连续性、内嵌图片有效性与数量分布、
四张关键表结构、字体与页面设置抽查、JSON 关键字段与正文一致性。

**输出解读**：脚本输出 `issues.json`（问题数组，含 level/location/desc/suggestion/source）。
- 脚本退出码 0 = 无 P0/P1；1 = 存在 P1；2 = 存在 P0（供自动化接续）。

### 第 3 步：图片视觉核对（AI 层，本技能核心）

图片核对是用户最关心的环节，必须逐张读图确认，不能只看脚本结果：

1. 运行图片提取脚本，把 docx 内嵌图片连同所在章节、上下文文字、图注一起导出：

   ```bash
   .../envs/default/Scripts/python.exe \
     (skill_dir)/scripts/extract_docx_images.py \
     --docx 验收报告.docx --out extracted_images/
   ```

   产物：`extracted_images/images/`（按出现顺序编号）+ `extracted_images/map.json`
   （每张图片的：序号、所在章节、前后文段落、图注文字）。

2. 用 Read 工具逐张查看图片（按 map.json 的序号顺序），逐项核对：

   | 核对项 | 判定要点 |
   |---|---|
   | 图注匹配 | 图片内容是否与图注/所在章节主题一致（如"附图1 地理位置图"处放的必须是地图，不是设施照片） |
   | 位置正确 | 地理位置图→附图；批复/许可证/CMA 章页/危废合同等扫描件→附件；设施照片→正文对应章节；错位即 P1 |
   | 方向 | 是否颠倒、侧转（扫描件常见） |
   | 清晰度 | 是否模糊、拉伸变形、分辨率过低（文字不可辨即 P1） |
   | 有效性 | 是否空白图、损坏图、重复插入同一张图 |
   | 编号连续 | 附图/附件序号是否 1,2,3… 连续无跳号重号（配合脚本结果） |

3. 记录每条问题的：图片序号、所在章节、问题描述、级别建议。
   注意：脚本只能判断"文件存在且非损坏"，**内容匹配必须靠本步 AI 视觉判断**。

### 第 4 步：内容与一致性核对（AI 层）

在脚本 JSON 比对结果之上，补充需要语义判断的检查：

- 验收结论与证据匹配：结论"通过验收"但正文存在《暂行办法》第八条不通过情形
  （重大变动未重新报批、无证排污、未验先投等）→ P0。
- 监测数据与限值：报告中限值、达标判定与监测数据逻辑自洽（超限必评价）；
  数据出处应为 CMA 报告，无法确认的标注"待人工核对原始监测报告"。
- 正文 ↔ 表格 ↔ 验收意见：总投资、环保投资、产能、规模、监测日期等关键数字三处一致。
- 文字质量：错别字、单位符号、标点、日期格式（YYYY年M月D日）、文号格式。
- 法定要素：报告标题、建设单位、编制单位、日期、盖章署名行是否齐全。

### 第 5 步：出具《报告审核意见单》

汇总脚本问题（source=脚本）与 AI 问题（source=AI），按 P0/P1/P2 分级排序，形成意见单：

| 级别 | 判定 | 结论 |
|---|---|---|
| P0 致命 | 存在任何一条 | **打回重做**：不得出具，先解决 P0 |
| P1 严重 | 存在任何一条 | **修改后复审**：全部 P1 修复后再审一次 |
| P2 一般 | 仅 P2 | **建议修改后通过**（或经用户确认可接受后通过） |

意见单结构：
1. 报告基本信息（文件、生成工具、审核时间、审核范围）。
2. 问题清单表格：`级别 | 位置(章节/页/图片序号) | 问题描述 | 修改建议 | 来源(脚本/AI)`。
3. 审核结论与依据（列出触发该结论的关键问题）。
4. 修改指引：若为本技能生成，指明"改 acceptance_data.json 的哪个字段 / 换哪张图 / 重跑生成"；
   若为外部报告，给出直接修改建议。

用 `deliver_attachments` 交付意见单（Markdown 或 docx），并在对话中给出结论摘要。

### 第 6 步：复审闭环（可选）

- 用户按意见单修改后重新生成/修改报告，回到第 1 步复审。
- 复审时优先核验上一轮 P0/P1 项是否清零，再跑全量检查。

## 捆绑资源

- `references/review_checklist.md`：P0/P1/P2 三级检查清单全文（图片/格式/内容三维度），
  及"可程序化项 vs 需 AI 项"的分工表。
- `scripts/check_acceptance_docx.py`：程序化检查脚本（章节/占位符/编号/图片有效性/
  表格/字体/页面/JSON 一致性），输出分级问题 JSON。
- `scripts/extract_docx_images.py`：从 docx 提取全部内嵌图片 + 上下文映射（供 AI 视觉核对）。

## 注意事项

- 审核不替代人工责任：监测数据真实性、现场情况的真实性最终由建设单位/监测机构负责，
  意见单中"待人工确认"项必须如实保留。
- 若报告同时存在 P0 与 P1，结论按 P0 处理（打回重做），P1/P2 一并列入问题清单。
- 与 ep-acceptance-report 的衔接：其生成的 docx 同目录通常有 `acceptance_data.json`，
  优先传入 `--data` 以获得一致性比对能力。
